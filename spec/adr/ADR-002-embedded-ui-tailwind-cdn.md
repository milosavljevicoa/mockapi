# ADR-002: Embedded UI with Tailwind CSS CDN

**Date:** 2026-10-28  
**Status:** Accepted

---

## Context

The dashboard needs to be delivered to the browser. Options considered:

1. Separate frontend project (React/Vue with a build step).
2. Server-rendered HTML templates (Go `html/template`).
3. Embedded static files (HTML + vanilla JS) using Go's `embed` package.

For CSS, options considered: a full local Tailwind build, the Tailwind Play CDN script, or writing custom CSS.

## Decision

The UI is built as plain HTML + vanilla JavaScript, embedded directly into the Go binary using the `//go:embed` directive. Tailwind CSS is loaded via the official CDN Play script (`<script src="https://cdn.tailwindcss.com">`).

## Rationale

- **Single binary**: No separate process, no static file directory, no npm install. One file to copy or deploy.
- **No build toolchain**: No Node.js, no webpack, no compilation step needed to build or modify the UI.
- **Tailwind CDN is acceptable**: This is a developer tool used on a machine that has internet access. The Play CDN generates all utility classes client-side; performance is sufficient for a local dev dashboard.
- **Vanilla JS is sufficient**: The UI is a three-panel inspector, not an application framework. DOM manipulation and `fetch` calls cover the full requirement without a framework's complexity.

## Consequences

- The dashboard requires an internet connection to load Tailwind CSS styles. If offline use becomes important, replace the CDN tag with an embedded precompiled Tailwind CSS file generated by the Tailwind CLI.
- UI updates require recompiling the Go binary. For minor style or layout changes during development, the `embed` directive can be temporarily replaced with a local file server.
- No hot reload or HMR — a browser refresh is sufficient and expected (manual refresh is the chosen update strategy).
